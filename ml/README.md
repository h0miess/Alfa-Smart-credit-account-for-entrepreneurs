# credit-scoring — PD-модель и кредитное решение для МСБ

Сервис оценивает риск дефолта заявителя (PD) и по кредитной политике выносит решение:
`APPROVED`, `COUNTER_OFFER`, `REQUEST_INFO`, `MANUAL_REVIEW` или `DECLINED`. Ответ включает условия,
причины и факторы, которые сильнее всего повлияли на оценку.

Скоринг и решение разделены, как в кейсе: модель даёт только оценку риска, а итог определяют
продукт, сумма, срок, стоп-факторы, платёжеспособность и залог (`decision.py`).

## Как устроено

```
заявка + обогащение (выписка, БКИ, ФНС — моки)
        │
        ▼
 стоп-факторы ──► DECLINED          (просрочка 90+, бизнес < 3 мес., не МСБ)
        │
 нехватка данных ──► REQUEST_INFO   (налоговый долг, мало оборотов через банк, нет залога)
        │
 PD-модель (LightGBM) ──► PD, балл, грейд A–E, вклад факторов (SHAP)
        │
 грейд E ──► DECLINED
        │
 лимит = min(платёжеспособность по оборотам, лимит продукта, залог)
        │
 триггеры андеррайтера ──► MANUAL_REVIEW  (> 30 млн, массовый адрес, грейд D + крупная сумма…)
        │
 сумма ≤ лимита ──► APPROVED
 иначе ──► COUNTER_OFFER (сначала дольше срок, потом меньше сумма) или DECLINED
```

| Файл | Что делает |
|---|---|
| `src/credit_scoring/synth.py` | генератор синтетических заявок с известным «истинным» процессом дефолта |
| `src/credit_scoring/features.py` | признаки, общие для обучения и инференса; монотонность; подписи факторов |
| `src/credit_scoring/train.py` | обучение, калибровка, валидация, сохранение артефактов |
| `src/credit_scoring/model.py` | инференс: PD, балл, вклад факторов |
| `src/credit_scoring/decision.py` | кредитная политика, продукты, ставки, лимиты |
| `src/credit_scoring/service.py` | HTTP API (FastAPI, Swagger на `/docs`) |
| `artifacts/` | обученная модель (`model.txt`), калибровка, `model_card.json` с метриками |

## Модель

- **Цель:** дефолт (90+ дней просрочки) в течение 12 месяцев.
- **Алгоритм:** LightGBM с монотонными ограничениями по 17 факторам (например, больше просрочек
  никогда не снижает риск), затем изотоническая калибровка PD.
- **Объяснения:** TreeSHAP, встроенный в LightGBM (`pred_contrib`). Отдельная библиотека не нужна.
- **Артефакты без pickle:** текстовая модель и JSON. Их можно ревьюить и безопасно загружать.
- **Ресурсы:** только CPU, обучение занимает около 10 секунд, ответ API — единицы миллисекунд.

### Валидация

150 000 синтетических заявок за 2023-01…2026-06. Обучение идёт на заявках до 2025-10, а метрики
считаются на более поздних (out-of-time):

| | Gini | KS | Brier |
|---|---|---|---|
| OOT, LightGBM | **0.687** | 0.535 | 0.0574 |
| OOT, логистическая регрессия (бейзлайн) | 0.677 | 0.523 | 0.0580 |
| Потолок: «истинный» PD генератора | 0.718 | — | — |

- Модель берёт ~96% достижимого качества. Остаток — скрытый стресс компании, которого нет в данных.
- Стабильность: PSI между разработкой и OOT = 0.0002.
- Калибровка по грейдам на OOT (прогноз → факт): A 1.1% → 1.1%, B 2.6% → 2.6%, C 5.5% → 5.9%,
  D 11.5% → 13.6%, E 36% → 37%.

**Ограничение:** модель обучена на синтетике. Метрики показывают, что пайплайн восстанавливает
заложенную зависимость, но ничего не говорят о качестве на реальном портфеле. Для прода нужно
переобучить модель на исторических заявках командой `train --data`.

## Запуск

```bash
uv sync
uv run python -m credit_scoring.train --out artifacts   # переобучить (артефакты уже в репо)
uv run pytest
uv run uvicorn credit_scoring.service:app --port 8000
```

Docker:

```bash
docker build -t credit-scoring ./ml
docker run -p 8000:8000 -e KEY_RATE=16.0 credit-scoring
```

| Переменная | По умолчанию | Смысл |
|---|---|---|
| `KEY_RATE` | `16.0` | ключевая ставка ЦБ, % — база для ставки по кредиту |
| `MODEL_DIR` | `artifacts/` | папка с артефактами модели |

## API

- `GET /health`
- `GET /v1/model` — версия, метрики, грейды, ограничения модели
- `GET /v1/products` — продукты и их параметры
- `POST /v1/score` — только риск: PD, балл, факторы
- `POST /v1/decision` — полное решение

Пример: `POST /v1/decision`

```json
{
  "application_id": "DEMO-1", "legal_form": "OOO", "industry": "services", "region_tier": 1,
  "business_age_months": 72, "employees": 25, "annual_revenue": 60000000,
  "avg_monthly_turnover": 4500000, "turnover_volatility": 0.15, "turnover_trend_12m": 0.15,
  "net_margin": 0.14, "existing_debt": 2000000, "monthly_debt_payments": 120000,
  "bki_history_months": 60, "max_overdue_days_12m": 0, "overdue_count_24m": 0,
  "credit_inquiries_3m": 0, "bank_client_months": 48, "cash_withdrawal_share": 0.05,
  "top_counterparty_share": 0.2, "product": "express", "requested_amount": 3000000, "term_months": 24
}
```

Ответ содержит `outcome`, `pd`, `score`, `grade`, `max_amount`, `offer` (сумма, срок, ставка, платёж),
`reasons`, `risk_factors`, `positive_factors`, `requested_documents`, `model_version`, `policy_version`.

## Продукты (вымышленные)

| Код | Продукт | Сумма | Срок | Особенности |
|---|---|---|---|---|
| `express` | Экспресс-кредит на оборотные средства | 0.1–10 млн | 3–36 мес. | без залога, ≤ 3 оборотов в месяц |
| `overdraft` | Овердрафт | 0.05–15 млн | 12 мес. | ≤ 50% месячных оборотов, +1 п.п. к ставке |
| `investment` | Инвестиционный кредит | 1–100 млн | 12–84 мес. | залог от 5 млн (покрытие ≥ 70%), −1.5 п.п. |

Ставка = ключевая + надбавка за грейд (A +3, B +5, C +7.5, D +10 п.п.) + поправка продукта,
и −1 п.п. при полном залоге.
